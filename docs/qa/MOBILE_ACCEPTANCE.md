# Ручная мобильная приёмка — ещё не выполнена

Это нативная игра Godot, не сайт/PWA. Для Android нужен APK; для iOS — экспорт
Xcode и подписанная установка. Safari не является способом запуска этого проекта.
Ни одна строка ниже не означает успешную проверку на телефоне.

## Сборка Android

1. Установить Godot **4.6.3** и его совпадающие export templates (Editor → Manage
   Export Templates). Установить JDK 17 и Android SDK согласно документации Godot
   4.6: platform-tools, command-line tools, platform/build-tools/NDK требуемых версий.
2. В Editor Settings → Export → Android указать Java SDK Path и Android SDK Path.
   В Export → Android проверить предложенные движком SDK versions; не подменять
   их случайными версиями из другой ветки Godot. Пресет включает arm64, portrait,
   immersive; интернет не запрашивается. Создать каталог export/android.
3. `org.mutantgarden.game` — рабочий идентификатор пресета. До публичной поставки
   владелец должен подтвердить уникальные package/bundle IDs и version code.
   Не менять ID уже установленной игры с прогрессом: это другой sandbox.
4. Выполнить `godot --headless --path . --export-debug Android export/android/MutantGarden.apk`.
   Установить через USB: `adb install -r export/android/MutantGarden.apk`.
   Не использовать `adb uninstall` или Clear Storage при тесте обновления.
5. Снять `adb logcat` с фильтром по PID игры. Для release/AAB нужен собственный
   signing keystore; хранить его и export_credentials.cfg вне Git. Ключи и подписи
   в этой задаче не создавались. APK/AAB в Git не добавлять.

## Сборка iOS

1. Нужны macOS, Xcode, matching Godot 4.6.3 templates, физический iPhone и Apple
   development signing. Создать export/ios. В пресете заполнить Team ID локально
   и проверить Bundle ID. Не коммитить сертификаты/ключи/профили.
2. Экспортировать iOS-проект из Godot. Открыть экспортированный Xcode project,
   выбрать Team/Automatic Signing, подключённый iPhone и выполнить Run.
3. Проверить Deployment Target/архитектуру через валидатор текущего Godot/Xcode.
   Для TestFlight нужны подпись и App Store Connect; загрузка/публикация в задачу
   не входила. Экспорт и установка iOS в Linux-сессии не выполнены.

Пресеты подготовлены, но нативная сборка не подтверждена: в среде нет matching
export templates, Android SDK/adb, macOS/Xcode и подключённых устройств. Наличие
JVM само по себе не является Android toolchain. PCK-проверка ресурсов не равна APK.

Для проверки времени не нужно ждать все 40 минут: морковь покрывает цикл 30 сек,
но хотя бы один долгий вид следует проверить в фоне. Фоновые процессы не нужны:
игра при старте/возврате вычисляет стадию по UTC timestamps. Смена часового пояса
не должна влиять на Unix time. Намеренную подмену часов локальная игра полностью
предотвратить не может. Системный Reduced Motion не читается через отдельный SDK;
в Godot-проекте есть собственная сохранённая настройка уменьшения анимаций.

Профилировать Android через Godot Remote Profiler/Android Studio, iOS через Xcode
Instruments. Цель — 60 FPS на подходящем устройстве; отдельно записать p95 frame
и затраты при открытии панелей/сборе. Не переносить числа llvmpipe на телефон.
Данные копировать только штатным debug sandbox-инструментом, перед экспериментами
с повреждениями делать backup всего user://. Не экспериментировать с единственным
пользовательским сохранением. Восстановление backup может вернуть предыдущую целую
транзакцию; нужен понятный отчёт об этом. Архивы .rejected-* сохраняют исходные байты.
